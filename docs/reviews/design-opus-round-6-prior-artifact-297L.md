## Minors

Carry-forwards that are still open in the current text, plus three new nits from this round.

- **OPUS-R6-N1 (lines 66, 236; = R5-N1, still open):** nothing asserts that `agent-home/extensions/prime-superpowers.js` is actually *discovered and loaded* from the isolated home. Line 236 asserts the home is active and that the package extension is filtered, which is a different property. The loader contract is `extensions/*.js|*.ts`, or `<dir>/index.js|.ts`, or `<dir>/package.json` with `pi.extensions` (`core/extensions/loader.ts:~464-543`); anything else is silently skipped, which was round 4's Blocker. Add an assertion over Prime's loaded-extension list.
- **OPUS-R6-N2 (lines 132-138; = R5-N2, still open):** the Gemini row is still presented as wire-authoritative. `google.ts:296-300` short-circuits `reasoning === "off"` into `getDisabledThinkingConfig`, which for a Gemini 3 Pro model returns `{thinkingLevel: "LOW"}` (`google.ts:417-423`) and never consults `thinkingLevelMap`; supported levels then flow through the hard-coded switch in `getThinkingLevel` (`google.ts:435-466`). So the design's Gemini `off: null` cell cannot produce a thinking-off wire, and the map's only real effect for Google is which levels survive clamping. Line 138's "no behavior depends on Prime's implicit defaults" and line 237's "emitted reasoning wires" test overstate the causal link for this row.
- **OPUS-R6-N3 (lines 55-81 vs 120; = R5-N3, still open):** `<kit>/.state/policy-history.jsonl` is still absent from the repository layout and its Git status is unstated. If it is clone-local and ignored, a fresh clone starts empty and the "three completed runs" demotion trigger never fires.
- **OPUS-R6-N4 (line 246 vs line 120; = R5-N4, still open):** stale test wording. Line 246 still tests "sealed **Sol** baseline ordering" while line 120 seals a per-gate *designated primary* that is deliberately not Sol at task gates. As written the implementation will encode only the spec/final case.
- **OPUS-R6-N5 (lines 83-90; = R5-N5, still open):** the four published SHA-256 values are recorded but no step compares them. npm enforces sha512 lock integrity, so line 90's "verifies the installed package identities and lockfile integrities" does not exercise the SHA-256 list. Either name the doctor step that re-fetches `SHA256SUMS` and compares, or label the list provenance-only.
- **OPUS-R6-N6 (lines 90, 230, 241; M3 residual):** the Node gate exists but its companions do not. There is still no npm floor (lockfileVersion 3 integrity for URL dependencies needs npm 7+), no note that `npm ci` will not enforce `engines` unless `engine-strict=true` is committed in `toolchain/.npmrc`, and `scripts/doctor`'s classification list at line 241 (unreachable, unauthorized, wrong path, incompatible dialect, missing model, unsupported effort) has no host-runtime category. Safety/compatibility line 230 still names only POSIX shells. Also unstated: which component performs the check — "Bootstrap" is not one of the named artifacts (`prime`, `prime.cmd`, `scripts/doctor`).
- **OPUS-R6-N7 (lines 174, 226; = R5-N6, still open):** the tarball's postinstall bootstraps `rg`/`fd`/the Python kernel only under `PRIME_AGENT_BOOTSTRAP_TOOLS_ON_INSTALL=1` / `PRIME_AGENT_BOOTSTRAP_KERNEL_ON_INSTALL=1`, which the design never sets, and runtime ensure-paths are interactive-mode only. Line 174's `rg`-based reconnaissance is therefore not guaranteed for headless children. State whether the kit sets those variables during `npm ci` or requires host-provided tools, and have doctor check both.
- **OPUS-R6-N8 (lines 202, 205, 209; new):** the extended-cache opt-out is under-specified in two ways that a literal implementer will get wrong. (a) Line 205 says "Empty overrides are rejected" in a paragraph that syntactically covers the same optional block as `PRIME_ANTHROPIC_EXTENDED_CACHE_BETA`, while line 209 says "the token may be empty only when the proxy explicitly does not require it" — scope the rejection rule to the URL overrides. (b) Say that an empty token **omits the header key** rather than sending `anthropic-beta:` with an empty value: header merging is a plain `Object.assign` over string values (`anthropic.ts:~225-233`), so an empty string is transmitted, not dropped, and a beta-validating gateway may reject it. While there, name the profile's `compat.supportsEagerToolInputStreaming` value explicitly instead of leaving it inside line 130's generic "compatibility flags" — the whole single-token argument depends on that flag being `true`, and a future profile edit to `false` would silently reintroduce round-5 M1 (line 237's paired test would catch it, but only because it happens to test both sides).
- **OPUS-R6-N9 (line 135; new, R5-M2 residual):** the Opus/Sonnet `off` → `off` cell is inert only by accident — `off` short-circuits before effort computation (`anthropic.ts:~809-811`), so the string is never used as an effort. Annotate it ("not sent; `thinking` disabled wire") or set it to `null`. Separately, the row exposes `low|medium|high|xhigh|max` where upstream's own `claude-opus-5`/`claude-sonnet-5` profiles declare only `{"xhigh":"xhigh","max":"max"}`. Deliberately widening the effort set for a proxy-fronted ID is defensible but should be stated as a decision with its rationale, since all five values now reach `output_config.effort` verbatim.
- **OPUS-R6-N10 (lines 146, 170, 231; = R5-N7, still open):** the vendored SDD script creates `<worktree>/.superpowers/sdd/<plan>/` with a self-ignoring `.gitignore` inside it. That is untracked and does not violate line 231's "never a tracked `.gitignore`", but line 231 does not acknowledge the generated file and line 170's coordinator write allowlist should name `.superpowers/sdd/` explicitly.

## Answers to the seat questions

- **Is the Anthropic beta story now correct in content, not just mechanism?** Yes. This is the first round where the header the kit sends and the body Prime builds agree. For `opus-5`/`sonnet-5`, 0.8.1 computes an empty beta set and marks tools `eager_input_streaming: true`; the kit adds exactly one token, for a purpose (one-hour retention) that Prime provably does not cover. The only fragility left is documentary: the deciding compat flag is not named in the model profile (N-8).
- **Can any dispatched effort still leave the provider's domain?** No. With `minimal` unsupported, clamping runs before the map is read, so every reachable `output_config.effort` is a member of `AnthropicEffort`. The `off` path never reaches effort computation at all.
- **Is the first-run setup contract complete?** For the failure that actually kills a Node 20 host, yes — the gate is present, ordered before `npm ci` and before credentials, with a distinct diagnostic, and its floor matches the artifact's `engines` exactly. What remains is triage quality rather than survivability: doctor still cannot name a host-runtime fault as such, and the npm floor and `engine-strict` caveat are unstated (N-6).
- **Any regression from the round-5 edits?** None found. The three edits propagated into the success criteria, the cache paragraph, the verification list, and the round-4 record, and no surviving sentence still describes the superseded two-token header or the `minimal` effort.
