## Majors

### OPUS-R5-M1 — The static Anthropic beta set is wrong for the only IDs the design allows

- **Affected lines:** 17, 209, 237 (also 127)
- **Spec claim:** line 209 — the static header contains `fine-grained-tool-streaming-2025-05-14` plus the extended-cache token and "intentionally replaces Prime's computed header with the complete set required for the only supported adaptive model IDs (`opus-5` and `sonnet-5`)". Line 17 elevates this to a success criterion ("the supported adaptive-thinking model IDs make the complete static beta set deterministic"), and line 237 tests the "exact static Anthropic beta set".
- **Evidence:**
  - The fine-grained token is emitted only when the model does **not** support eager tool-input streaming: `packages/ai/src/providers/anthropic.ts:1215-1217` — `shouldUseFineGrainedToolStreamingBeta = !!context.tools?.length && !getAnthropicCompat(model).supportsEagerToolInputStreaming`.
  - That compat flag **defaults to `true`**: `anthropic.ts:173-178` — `supportsEagerToolInputStreaming: model.compat?.supportsEagerToolInputStreaming ?? true`.
  - Upstream declares `compat: {"supportsEagerToolInputStreaming": false}` only for older models (`claude-haiku-4.5`, `claude-sonnet-4`, `claude-sonnet-4.5` in `packages/ai/src/models.generated.ts`); `claude-opus-5` and `claude-sonnet-5` carry **no** compat block, so they take the `true` default.
  - Consequently, for `opus-5`/`sonnet-5` Prime 0.8.1 computes an **empty** `betaFeatures` array — interleaved is skipped for adaptive models (`anthropic.ts:851-853`) and fine-grained is skipped by the compat default — so no `anthropic-beta` header is sent at all (`anthropic.ts:932-939`).
  - The two settings are mutually exclusive by construction: with eager streaming the request instead marks every tool `eager_input_streaming: true` (`anthropic.ts:994-999,1230-1233`).
- **Concrete failure:** the kit sends `anthropic-beta: fine-grained-tool-streaming-2025-05-14,extended-cache-ttl-2025-04-11` on every turn *together with* `eager_input_streaming: true` tools — a combination Prime never emits and that the upstream code treats as alternatives. Round 4's B3 evidence ("true for essentially every agent turn") assumed compat `false`; the design faithfully implemented a false premise. Best case the extra token is inert and line 209's "complete set required" is simply untrue while line 237's test enshrines it; worst case a beta-validating gateway or the upstream API rejects the pair, and because every agent turn carries tools, the failure is total rather than intermittent. Either way the only token the design actually needs for its stated purpose (one-hour retention) is the extended-cache token.
- **Required change:** state the model profile's `compat.supportsEagerToolInputStreaming` explicitly and make the static set follow from it. If the profile keeps the upstream default (`true`, i.e. `eager_input_streaming` tools), the static header must be `PRIME_ANTHROPIC_EXTENDED_CACHE_BETA` alone. If the profile declares `false`, keep both tokens and say that tools are then sent without `eager_input_streaming`. Line 237's test must assert the pairing (declared compat ⇔ emitted beta set ⇔ tool-level `eager_input_streaming`), not just a hard-coded token list.

### OPUS-R5-M2 — The Opus/Sonnet thinking map specifies an effort value 0.8.1 cannot send

- **Affected lines:** 130-138 (consequences at 112, 237)
- **Spec claim:** line 135 maps Opus/Sonnet `minimal` → `minimal` (and `off` → `off`); line 138 asserts "Supported values preserve the matching 0.8.1 provider behavior" and that "no behavior depends on Prime's implicit defaults".
- **Evidence:**
  - For adaptive models the map value is used verbatim as the effort: `anthropic.ts:813-821` → `mapThinkingLevelToEffort` (`:766-796`) returns `model.thinkingLevelMap[level]` whenever it is a string, casting it `as AnthropicEffort`.
  - `AnthropicEffort` is `"low" | "medium" | "high" | "xhigh" | "max"` (`anthropic.ts:166`); `minimal` is not a member. Prime's own fallback for a `minimal` request is `"low"` (`anthropic.ts:786-789`).
  - The effort is placed unfiltered on the wire: `anthropic.ts:1009-1020` sets `params.thinking = {type:"adaptive"}` and `params.output_config = {effort: options.effort}`.
  - Declaring a non-null value also makes the level "supported", so `clampThinkingLevel` (`packages/ai/src/models.ts:78-97`) will no longer rewrite it — the invalid value cannot be caught downstream.
  - Upstream's own `claude-opus-5`/`claude-sonnet-5` profiles declare `thinkingLevelMap: {"xhigh":"xhigh","max":"max"}` only, i.e. upstream deliberately exposes just two efforts for these IDs.
- **Concrete failure:** any seat dispatched at `minimal` on Opus or Sonnet emits `output_config.effort: "minimal"`, an effort the provider's own type set rejects; the request 400s at the gateway or is silently coerced. Exposure is narrow today (the role table dispatches Opus/Sonnet at `high`, and line 116's cheap re-review seat varies the *model*, not the level), so this is not a first-run Blocker — but it is a verified-false normative value inside the table the design calls exact, and line 237's "seven-entry truth tables plus emitted reasoning wires" test would encode it. `off` → `off` is inert only by accident (level `off` short-circuits before effort computation at `anthropic.ts:809-811`) and should be documented as such or set to `null`.
- **Required change:** set Opus/Sonnet `minimal` to `low` (matching 0.8.1's fallback) or to `null` (unsupported, clamped), and annotate the `off` cell as "not sent; `thinking: {type:"disabled"}` wire" with `anthropic.ts:809-811,1028-1030` as the citation. State whether the kit intentionally widens the level set beyond upstream's `xhigh`/`max` for these IDs, and why that is safe on the proxy.

### OPUS-R5-M3 — The design never states its hard Node runtime prerequisite

- **Affected lines:** 11, 83-90, 241 (also 230)
- **Spec claim:** line 11 — the common case "requires only `PRIME_BASE_URL` and `PRIME_LLM_KEY`"; line 90 — `npm ci` then "requires `--version` 0.8.1"; line 241 — doctor "distinguishes unreachable, unauthorized, wrong path, incompatible dialect, missing model, and unsupported effort".
- **Evidence:** the installed package declares `engines: {node: ">=22.8.0"}`. In this sandbox (Node v20.20.1, npm 10.8.2) `npm ci` **succeeded** with only `npm warn EBADENGINE`, and the resulting binary then refused to run: `prime-agent requires Node 22.8.0 or newer, but the active Node is v20.20.1` with exit status **1**. No line of the design mentions Node, npm, or a toolchain-version check; `scripts/doctor` (line 241) has no host-runtime category, and Safety/compatibility (line 230) names only POSIX shells.
- **Concrete failure:** on any host still on Node 20 LTS — the default on many macOS/Linux/WSL setups — a fresh clone installs cleanly and then dies at the pre-credential version gate with a message that never mentions 0.8.1, so the launcher's own diagnostic ("version mismatch") misattributes a host-runtime problem. The failure is loud and fail-closed, which is why this is Major and not Blocker, but the design's setup contract is incomplete and doctor cannot classify the most likely first-run failure.
- **Required change:** add Node `>= 22.8.0` (and an npm floor that supports lockfileVersion 3 integrity for URL deps, i.e. npm 7+) to the configuration/compatibility section, have `scripts/doctor` and the launcher check `node --version` **before** `npm ci`, and distinguish "unsupported host Node" from "wrong Prime version" in the version-gate diagnostic. Note that `npm ci` will not enforce this for you unless `engine-strict=true` is committed in `toolchain/.npmrc`.

## Minors

- **OPUS-R5-N1 (lines 66, 236):** B2's requested regression guard is missing. Line 236 asserts the isolated home is active and the package extension is filtered, but nothing asserts that `agent-home/extensions/prime-superpowers.js` is *discovered and loaded* from the isolated home (the exact silent-skip failure of round 4). Add an assertion over Prime's loaded-extension list, and note that the discovery contract is `extensions/*.js|*.ts` or `<dir>/index.js|.ts` or `<dir>/package.json` with `pi.extensions` (`core/extensions/loader.ts:464-543`) — a nested file without one of those forms is silently ignored.
- **OPUS-R5-N2 (lines 132-138):** the Gemini row is not wire-authoritative. `providers/google.ts:435-466` (`getThinkingLevel`) derives `thinkingConfig.thinkingLevel` from a hard-coded switch on the clamped pi level and never reads `thinkingLevelMap`; for `gemini-3.1-pro` it emits `LOW` for minimal/low and `HIGH` for medium/high, and `off` is routed to `getDisabledThinkingConfig` → `{thinkingLevel: "LOW"}` (`google.ts:417-423`), never to the map. The design's `LOW`/`HIGH` values happen to coincide, but the map's only real effect for Google is which levels survive clamping. Say so, or line 237's "emitted reasoning wires" test will assert a causal link that does not exist.
- **OPUS-R5-N3 (lines 55-81, 120):** `<kit>/.state/policy-history.jsonl` is the durable seat record M3 asked for, but it is absent from the repository layout and its Git status is unspecified. Since it lives in the clone, a fresh clone starts empty and the "three completed runs" trigger never fires; state whether the file is committed (auditable, mutable-by-run) or ignored (then name where cross-run history actually accumulates).
- **OPUS-R5-N4 (line 246 vs line 120):** stale test wording. Line 246 tests "sealed **Sol** baseline ordering" while line 120 seals a per-gate *designated primary* that is deliberately **not** Sol at task gates. Re-word the test to the primary-seat contract, or the implementation will encode the spec/final case only.
- **OPUS-R5-N5 (lines 83-90):** the four SHA-256 values are correct and the R2 artifacts are byte-identical to the GitHub assets today, but nothing says who compares them. npm enforces **sha512** lock integrity, so the recorded SHA-256 list is documentation unless doctor re-downloads and compares it against the release `SHA256SUMS`. Name the comparison step, or label the list as provenance-only and rely on the lock.
- **OPUS-R5-N6 (lines 174, 226; round-4 N2 residual):** the tarball's `postinstall.cjs` bootstraps `rg`/`fd`/the Python kernel only when `PRIME_AGENT_BOOTSTRAP_TOOLS_ON_INSTALL=1` / `PRIME_AGENT_BOOTSTRAP_KERNEL_ON_INSTALL=1` (verified in the installed `dist/postinstall.js`), which the design never sets. At runtime `fd`/`rg` are ensured only on the interactive path (`modes/interactive/interactive-mode.ts:1364`, `modes/agents-view/agents-view-mode.ts:728`) and the kernel on first REPL use (`core/kernel/repl-manager.ts:185`). Line 174's `rg`-based reconnaissance is therefore not guaranteed in `-p`/headless children. State whether the kit sets the bootstrap env vars during `npm ci` or requires host-provided tools, and have doctor check both.
- **OPUS-R5-N7 (lines 146, 231):** the vendored SDD scripts write into the target worktree: `scripts/sdd-workspace` creates `<worktree>/.superpowers/sdd/<plan>/` plus a **self-ignoring `.gitignore`** inside it (upstream `skills/subagent-driven-development/scripts/sdd-workspace:6-16,36`). That is untracked and does not touch a tracked `.gitignore`, so it does not violate line 231 — but line 231 says "never a tracked `.gitignore`" without acknowledging this generated one, and line 170's root-contract write allowlist should name `.superpowers/sdd/` explicitly.

## Answers to the seat questions

- **Is the boot chain now executable?** Yes, for the first time. All three round-4 Blockers are closed, and I verified the two supply-chain ones against the live artifacts rather than by reading: `npm ci` of the pinned tarball produces a real `prime-agent` shim, the lock carries integrity for the GitHub entry and all three R2 internal tarballs, integrity tampering fails closed with `EINTEGRITY`, and the extension filename now matches the loader's contract with jiti handling ESM. The remaining execution risk is environmental, not architectural (M3: undocumented Node ≥ 22.8.0).
- **Is the Anthropic beta story correct?** The *mechanism* is correct and I traced it to the merge site; the *content* is not. For `opus-5`/`sonnet-5` Prime 0.8.1 sends no `anthropic-beta` header at all, so the design's "complete set required" is a superset that contradicts the `eager_input_streaming` tool shape the same request carries (M1).
- **Is the per-task council policy falsifiable now?** Yes in substance. Sealing a primary finding set at every gate, attributing unique accepted findings per seat, and persisting seat statistics with a three-run demotion threshold makes the removal rule fireable where the admissions are actually spent. What remains is bookkeeping hygiene: where the cross-run file lives and whether it survives a fresh clone (N3), and one stale test name (N4).
